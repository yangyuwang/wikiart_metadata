# Next Steps

## 1. Create dataset of images + descriptions

Create a dataset in csv format with the columns `filepath,caption`. See example in the "Beginners guide to fine-tuning OpenClip" for more details.
I would suggest to create multiple captions for the same image with a range of different templates.

Example:

- `An painting from {artist} in the year of {year}.`
- `An painting from an artist living in {city} in the year of {year}.`
- `An painting from an {ethnicity} artist in {city} in the year of {year}.`
- ...

You might want to add an additional column to the dataset to indicate the template used.

Alternative, and maybe better:
You create a method that creates a caption from the metadate, and you allow individual information
to be included or excluded from the caption.

Then you dataset could look like this:
`filepath,caption,wArtist,wYear,wCity,wEthnicity`

The `w` stands for "with". If the value is 1, the information is included in the caption. If the value is 0, the information is excluded from the caption.

## 2. Fine-tune Dreambooth

If we want to fine-tune a model that is able to generate images from the caption, we might want to use the Dreambooth method. This method has
mainly been used to create a models with a single distinct style. However, we can also use it to fine-tune a model on a dataset of images and
captions.

You can read about the general method here: https://huggingface.co/docs/diffusers/en/training/dreambooth

Many existing scripts use a fixed prompt for all images and only train on 10 - 20 images. We want to train on much more images and use different
prompts for each image. In principle that should be possible, but we need to see how well it works in practice and how resource intensive it is.

Flux is one of the best text-to-image models. So I would suggest to used it.

There is a README on how to use dreambooth with flux: https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_flux.md

Important parameters unique to what we want to do:

- image_column: The column in the dataset that contains the image paths.
- caption_column: The column in the dataset that contains the captions.
- train_text_encoder: Set to true. We want to fine-tune the text encoder to be able to understand our captions. (You might experiment setting this to false initially to stabilize the training and reduce resource usage)
- num_train_epochs: The number of epochs to train the model.

I would recommend to train only a single epoch. You might otherwise overfit.

I would recommend to start with a small dataset of 1000 images and captions. You can always increase the dataset size later.

I would recommend to go for the default parameters for the other settings. You might want to experiment with the learning rate, warmup steps, batch size, lora rank, etc. later.

I would suggest trying to use LORA to train the model (initially). This might be more stable and faster.

An important consideration is whether to train the text encoder or not. If we train the text encoder, it might better make use of the
full information in the captions. However, then we most likely will not be able to use the model to generate images from captions that do not
follow the original templates.

Make sure that you setup a Weights & Biases account and use it to log the training process. Unfortunately, the script does not seem
to allow to provide a validation dataset. However, the training loss will already give you a good indication of if the model is learning
something useful.

## 3. Evaluate the model

### 3.1. Generate images from captions

Make sure that you leave out a validation set when training the model. After training, create some images from the captions in the validation set.
Compare qualitative the images generated with the true images. Compare the images generated with different templates.

### 3.2. Compute loss between image and caption

Split your validation set into subsets based on the template used. Compute the loss of of the image and the caption for each subset. This will give an
indication how much the information in the different templates contribute to the prediction of the image.

## Data Storage

I send your earlier the credentials to use our MinIO storage. You can use this to store the dataset and the model checkpoints.

You can use the `mc` command line tool to upload and download files from the storage. You can find the documentation here:
https://min.io/docs/minio/linux/reference/minio-mc.html#quickstart

First setup you environment to use MinIO:

```bash
export MINIO_ACCESS_KEY=...
export MINIO_SECRET_KEY=...
export MINIO_URL=...
export MINIO_BUCKET=...
```

Then setup the `mc` command line tool to use the storage:

```bash
mc alias set mpib $MINIO_URL $MINIO_ACCESS_KEY $MINIO_SECRET_KEY
```

Then you can use `mc` to upload and download files from the storage.

For example, to upload a file:

```bash
mc cp my_file.csv $MINIO_BUCKET
```

Or to download a file:

```bash
mc cp $MINIO_BUCKET/my_file.csv .
```

Display the content of the bucket:

```bash
mc ls $MINIO_BUCKET
```
